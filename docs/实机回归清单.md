# Notchly 实机回归清单

适用于每个 Alpha 发行包。自动测试通过后，至少在一台带刘海的 Mac 上完成以下检查，并记录 macOS 版本、应用版本和构建号。

## 启动与刘海交互

- 冷启动后，紧凑岛出现在内建刘海两侧，鼠标不被透明区域拦截。
- 悬停、菜单栏图标和 `⌘⇧Space` 都能展开；点击岛外或 `Esc` 能收起。
- “内建屏”策略下，连接外屏后岛仍留在带刘海的内建屏；改变系统主屏不影响它。
- “主屏”策略下，岛位于 macOS 主菜单栏所在屏幕；改变主屏后会自动重新定位。
- “随鼠标”策略下，鼠标跨屏后收起岛会移到新屏幕；展开交互期间不应跟随鼠标跳走。
- 在无刘海外屏上，岛应位于顶部中央，展开、收起、点击和悬停命中区一致。
- 分别测试左/右/上下排列外屏、改变主屏、热插拔及睡眠唤醒；岛不得留在已断开屏幕的坐标上。
- 视频、游戏或演示进入 macOS 全屏空间后，默认不显示紧凑岛；退出全屏后自动恢复。
- 关闭“全屏时自动隐藏”后，紧凑岛仍可进入其他应用的全屏空间。
- 分别切换“智能 / 时间 / 极简”收起状态，宽度与内容应立即变更，悬停可点区与可见黑色岛保持一致。
- 播放包含中英文长歌词的歌曲，收起状态不得出现歌词，也不得向下覆盖浏览器；展开播放器和桌面歌词仍应正常同步。
- 在时间模式下检查时钟与专注倒计时的优先级；极简模式下空闲时不应出现额外文字。

## 播放器与歌词

- 分别使用 Apple Music、Spotify、网易云音乐、QQ 音乐、酷狗、酷我和汽水音乐，确认诊断信息中的当前适配器分别显示 AppleScript 或 MediaRemote。
- 同时打开公开通道播放器和国内播放器：国内播放器正在播放时应优先显示；国内播放器暂停时应优先显示正在运行的 Apple Music / Spotify。
- 在两个通道间反复切歌、暂停、退出和重新打开播放器，确认上一曲、播放/暂停、下一曲始终路由到当前显示的播放器。
- 国内播放器全部退出后，MediaRemote 监听应停止；之后启动国内播放器应重新建立监听且不重复启动辅助进程。
- 长时间播放后复制诊断信息，确认 AppleScript 与 MediaRemote 分栏计数合理；一次成功应把对应通道的“连续失败”归零，且内容中没有歌曲名、脚本原文或账号信息。
- AppleScript 通道短暂失败但 MediaRemote 仍保留有效状态时，灵动岛应继续显示兼容通道内容，诊断中的 AppleScript 失败与降级次数应增加，而不是直接清空播放器。
- 让 Apple Music 或 Spotify 暂时无响应，确认单次自动化调用最多等待约 8 秒；连续失败后诊断出现限流和冷却时间，CPU 不因高频重试持续升高。
- 播放器恢复后等待下一次试探，确认歌曲信息重新出现、“连续失败”归零且“冷却至”恢复为“无”。
- 连续切换至少 3 首歌后，“音乐记录”中的最近播放按新到旧排列；重复播放同一首歌只更新位置和次数，不生成重复条目。
- 收藏当前歌曲后，切歌并重启 Notchly，收藏仍保留；清空最近播放不会清空收藏。
- 使用长歌名、长歌手名测试最近播放与收藏列表，文字应单行截断且按钮不被挤出。
- 分别用 Apple Music、Spotify 和任一系统媒体兼容播放器测试播放、暂停、上一曲、下一曲和打开来源应用。
- 在播放器短暂无响应时，岛的展开、收起和鼠标交互不能冻结；控制失败须显示可理解的提示。
- 切歌、暂停、拖动播放器进度后，封面、进度和歌词在合理时间内同步；无歌词和网络失败不应持续高频请求。
- 播放歌词源带译文的外语歌曲，灵动岛和桌面歌词应显示当前句原文与译文；关闭“显示翻译”后立即恢复单语。
- 播放没有译文的歌曲时应自动保持原文与下一句显示，不出现空白占位；长译文应截断或缩放，不挤压控制按钮。
- 开启/关闭桌面歌词，检查锁定穿透、解锁热点、拖动位置记忆、KTV 覆盖和暂停后的动画停止。
- 依次切换桌面歌词的“单行 / 双行居中 / KTV 交替”：单行应居中，双行应整组向上淡出淡入，KTV 应在左上与右下固定轨道交替点亮。
- 在开启“显示翻译”时检查双行居中第二行优先显示当前句译文；KTV 交替仍保持两句原文轨道。

## 文件托盘与系统服务

- 依次套用工作、音乐、演示和省电场景，确认设置说明与悬停、全屏、收起状态和桌面歌词一致，核心模块始终保留。
- 套用任意场景后手动修改关联设置，场景应立即变为“自定义”。
- 省电场景下确认装饰动效停止、媒体轮询降频，收起状态不运行时间或进度时间线；电池等核心入口仍可正常使用。
- 演示场景下鼠标划过不会自动展开，全局快捷键和菜单栏入口仍可手动打开。
- 设置页不再显示“模块卡片”；播放时快捷栏固定为四个等宽入口。
- 首次启动时不应主动请求提醒事项权限，只有在无音乐待机面板中打开提醒卡片后才请求权限。
- 允许提醒事项权限后，确认优先显示截止时间最早的未完成提醒，逾期项目带有“已逾期”提示，无截止时间时有明确回退文案。
- 拒绝或撤销提醒事项权限后，卡片显示可理解的授权提示。
- 点击提醒卡片中的“打开提醒事项”，确认系统提醒事项应用正常打开。
- 播放时快捷栏和无音乐待机面板应始终使用稳定默认顺序。
- 点击“恢复默认”，确认只重置当前选中区域的顺序，模块仍保持必选。
- 播放时快捷栏中文件暂存应始终位于末尾，连续调整顺序时没有挤压或跳动。
- 导入小文件、大文件、同名文件和目录；验证导入期间岛仍可操作、容量限制准确、重名副本不覆盖原件。
- 导入期间“一键清空”应不可用；导入成功、失败和容量不足都应给出正确状态。
- 日历授权拒绝/允许后，显示内容与提示正确；电池信息在展开和收起状态均可刷新。
- 专注、喝水和久坐提醒在开关切换后正确创建或取消。

- 对外分发前，完成 Developer ID 签名、公证与隐私/私有 API 风险复核。
