# 发布准备清单

适用于 Notchly 公开 GitHub 仓库与 macOS Alpha 发行。本文不是法律意见；涉及主体信息、许可证、版权、隐私合规和商标时，应由发布主体确认。

## 先确定两项不可替代的决定

- [x] **代码许可证**：采用 MIT License，允许使用、修改和分发，同时保留版权与许可文本。当前版权主体按公开仓库维护者 `lglglglglg` 标注；若改用个人、工作室或公司主体，须在公开发行前同步更新 `LICENSE` 与应用内版权字段。
- [ ] **发行路径**：当前建议优先选择官网 / GitHub Release 的 Developer ID 签名与 Apple 公证。由于国内播放器兼容层使用私有 `MediaRemote.framework`，不要将当前功能集直接提交 Mac App Store。

## 公开 GitHub 仓库

- [x] README：说明用途、运行方式、已知限制和本地验证。
- [x] `PRIVACY.md`：说明权限、本机存储、歌词和封面第三方请求。
- [x] `CHANGELOG.md`：维护用户可见改动。
- [x] `CONTRIBUTING.md`：约束验证、隐私数据和构建产物。
- [x] `THIRD_PARTY_NOTICES.txt`：保留 MediaRemoteAdapter BSD-3-Clause 通知并随应用打包。
- [x] GitHub Actions：push / pull request 执行构建和测试。
- [x] `LICENSE`：仓库根目录采用标准 MIT 文本。
- [ ] 在 GitHub 仓库设置中配置 description、topics、Issues 和 Discussions 策略。
- [ ] 配置私密安全报告渠道（Security Advisories 或安全联系邮箱），再添加 `SECURITY.md`。
- [ ] 单独审核 `docs/使用截图/`：剔除用户名、日历、文件名、序列号、通知和其他个人信息后再提交。
- [ ] 推送前执行 `git status`，确认没有 `dist/`、archive、证书、私钥、令牌或本机构建缓存。

## 官网 / GitHub Release 分发（建议路径）

- [x] Release 配置已启用 Hardened Runtime；App Sandbox 和最小权限在工程中声明。
- [ ] 在 Xcode 中为 Release 选择 Apple Developer Program 团队与 Developer ID Application 证书。
- [ ] Archive 后使用 Developer ID 签名，验证所有嵌入 framework 都已正确签名。
- [ ] 用 Apple notary service 公证并 stapler 固化票据；在未参与开发的测试 Mac 上验证安装、启动、自动化权限和文件托盘。
- [ ] 创建版本标签（如 `v0.12.5`）和 GitHub Release，上传经公证的 ZIP、DMG 或 PKG，并提供 SHA-256 校验值、最低系统版本、已知限制和回滚说明。
- [ ] 在一个带刘海的 Mac 上执行 [实机回归清单](实机回归清单.md)，并记录 macOS、版本和构建号。
- [ ] 为稳定渠道确定更新机制后，再在应用内启用“检查更新”；发布前该按钮必须保持诚实地说明未接入更新通道。

## Mac App Store 路径（当前阻塞）

- [ ] 移除或功能降级依赖私有 `MediaRemote.framework` 的国内播放器兼容层，并仅保留通过公开 API 能合规实现的功能。
- [ ] 使用 App Store Connect 填写隐私、版权、支持 URL、营销素材、年龄分级和导出合规信息。
- [ ] 用 App Store 构建配置重新验收全部权限说明、沙盒行为和第三方服务声明。

## 每个版本的最小验收命令

```sh
swift test
xcodebuild -project Notchly.xcodeproj -scheme Notchly -configuration Debug CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Notchly.xcodeproj -scheme Notchly -configuration Release CODE_SIGNING_ALLOWED=NO build
```
