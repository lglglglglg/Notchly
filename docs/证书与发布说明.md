# Notchly 证书与发布说明

本文说明 Notchly 从本地构建到 GitHub Release 的签名、公证和验收边界。它只记录流程，不包含任何证书私钥、App Store Connect API Key 或登录凭据。

## 推荐发布路径

当前 Notchly 依赖国内播放器兼容层使用的私有 `MediaRemote.framework`，不建议直接提交 Mac App Store。公开发行优先采用：

1. Apple Developer Program 的 **Developer ID Application** 证书签名；
2. Hardened Runtime；
3. Apple notary service 公证；
4. stapler 将公证票据固化到应用或归档；
5. 在一台未参与开发的 Mac 上安装验证。

## 证书准备

- 在 Xcode 的 Signing & Capabilities 中选择正确的 Team，并确认 Release 使用 Developer ID Application 证书。
- 本地脚本通过环境变量 `NOTCHLY_SIGNING_IDENTITY` 接收签名身份名称；默认值 `-` 只生成 ad-hoc 测试包。
- 证书私钥、`.p12`、App Store Connect API Key、`notarytool` 密码、临时令牌和钥匙串导出文件不得提交到 Git。
- 发布前确认 `Notchly/Notchly.entitlements` 只包含实际使用的最小权限，并检查 `Info.plist` 的用途说明与功能一致。

## 构建与本地验签

```bash
xcodegen generate
NOTCHLY_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
  ./scripts/package-stable.sh

codesign --verify --deep --strict --verbose=2 dist/Notchly.app
codesign -dvvv --entitlements :- dist/Notchly.app
spctl --assess --type execute --verbose=4 dist/Notchly.app
shasum -a 256 dist/Notchly-0.13.9-alpha.zip
```

脚本会生成 `dist/Notchly.app` 和版本化 ZIP。使用正式 Developer ID 证书时，建议在干净钥匙串和干净构建目录执行。

## 公证示例

以下命令只展示流程，凭据应通过 macOS 钥匙串或 CI 的受保护密钥注入：

```bash
xcrun notarytool submit dist/Notchly-0.13.9-alpha.zip \
  --keychain-profile "NOTCHLY_NOTARY" \
  --wait

xcrun stapler staple dist/Notchly.app
xcrun stapler validate dist/Notchly.app
spctl --assess --type execute --verbose=4 dist/Notchly.app
```

公证完成后重新计算 ZIP 的 SHA-256，并在 GitHub Release 中同时提供版本号、最低 macOS 版本、已知限制和校验值。

## 发布前检查

- [ ] 版本号和构建号在 `project.yml`、应用 About 页和 Release 标题中一致
- [ ] `LICENSE`、README、Info.plist 与 About 页统一显示 Stephan Li / Hanshijiu Studio
- [ ] `PRIVACY.md` 准确列出歌词、封面、日历、通知、自动化和文件托盘的数据边界
- [ ] 未提交证书、私钥、令牌、DerivedData、archive 或本地日志
- [ ] 在带刘海和不带刘海的 Mac 上分别验证展开、收起、权限、通知和文件托盘
- [ ] 在未参与开发的 Mac 上安装并验证签名、公证、首次启动和卸载
